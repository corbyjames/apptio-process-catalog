# Contributing

## Golden rule

**`data/catalog.json` (plus the small `data/*.yaml` files) is the source of truth for content; `diagrams/bpmn/custom/` and
`diagrams/drawio/` are the source of truth for hand-refined diagrams.** Everything else is
regenerated by CI on merge to `main` — don't hand-edit generated files (your changes will be
overwritten).

## Workflow

1. Branch from `main`, make your edit, open a PR.
2. For content edits, change `data/catalog.json` (or `calendar.yaml`, `tool-config.yaml`,
   `frameworks.yaml`, `l0-links.yaml`). Keep positional IDs stable — diagrams and configuration
   backlogs reference them — and give new L2s the next free element ID (`P-0150`, …) and new L1s
   the next `G-` ID. Flow steps: `n`, `type` (BPMN element), `lane`, `task`, `note`, `l2` (the
   catalog processes the step invokes).
3. For diagram edits, use one of:
   - **Mermaid**: don't edit the generated Mermaid — change the underlying data instead.
   - **BPMN**: open the model in the Pages **viewer/editor** (`site/viewer.html`), or bpmn.io /
     Camunda Modeler. Save the edited XML into `diagrams/bpmn/custom/<name>.bpmn`.
     If you start from a generated file, copy it into `custom/` first — files under
     `generated/` are rebuilt from data on every merge.
   - **draw.io**: edit `diagrams/drawio/*.drawio` at diagrams.net or in VS Code.
4. Reviewers see readable diffs for YAML, Mermaid, and BPMN XML alike.
5. On merge, GitHub Actions regenerates `docs/`, `diagrams/mermaid/`,
   `diagrams/bpmn/generated/`, `assets/diagrams/`, `site/`, `dist/` and deploys the Pages site.

## Content conventions

- L2 descriptions: one or two sentences, active voice.
- `personas`: comma-separated; **the first entry that matches one of the area's default lanes
  becomes the BPMN lane** (keyword tables in `scripts/bpmn.py`). `persona_list` is the normalized
  16-role vocabulary shown in the *Who* chips.
- `delivery_model`: `Any` (methodology-agnostic), `Agile`, `Traditional`, or `Hybrid`
  (explicitly about running agile + traditional together).
- `config`: the tool objects a consultant would set up for that activity.
- `evidence`: where the claim comes from (deck, demo, docs, framework) — keep it honest; mark
  unverified items "verify".

## Local build

    pip install -r scripts/requirements.txt
    python scripts/generate.py          # regenerate everything (site, docs, BPMN, SVG, xlsx)
